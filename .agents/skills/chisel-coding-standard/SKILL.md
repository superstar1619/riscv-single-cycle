# Chisel 编码与评审

为教材配套 Chisel 硬件提供生成、修改和评审指导。中文说明，保留英文代码标识符。

## 先读取依据

读取 [中文编码规范](../../../docs/chisel-coding-standard.md)，它是条款与示例的唯一完整来源。
相对路径以本 `SKILL.md` 所在目录解析，不以执行命令的 cwd 解析。
然后读取任务所在项目的 `AGENTS.md`（若存在）、构建文件和相关模块/测试。
当前项目是 Scala 2.13.14、Chisel 3.6.1；迁移后以实际构建依赖为准。
规范文件缺失时说明缺失位置，继续可独立完成的工作，不声称已按完整规范验证。

明确用户要求与已有接口契约优先。这个 skill 不授权修改无关文件、升级依赖、提交代码、
发布、全局安装，或自动进入项目的下一轮硬件实现。

## 编写或修改硬件

先从需求和现有代码确认：组合/时序属性、接口名称与方向、位宽与符号含义、
时钟/复位域、延迟、配置支持范围。能从工程查到的信息不重复问用户。

遵循规范 §1–§7；优先保持本工程硬件大驼峰和现有小写通用端口，
Scala 配置/参数小驼峰。只对真实流水线使用阶段后缀。
保持已验收的显式 `clk/reset` 和纯组合 `RawModule` 接口；
迁移到采用 `Module` 的其他工程时保持其原有时钟约定。

在受影响逻辑上逐项核对：

| 关注点 | 要确认的结果 | 规范位置 |
| --- | --- | --- |
| 位宽与算术 | 进位是否保留，截断/扩展与符号比较是否符合需求 | §3 C1–C3 |
| 生成与硬件条件 | 配置 if/for 与运行时 when/Mux 是否正确区分 | §4 C4 |
| 组合驱动 | 默认值完整，覆盖顺序/优先级明确；DontCare 不作安全零 | §4 C5 |
| 状态与复位 | 保持、更新抑制、复位值与复位类型分别符合契约 | §5 C6 |
| 存储器 | 延迟、地址单位、初始化与同址读写契约明确 | §5 C7 |
| 接口连接 | 字段、方向与宽度兼容，聚合连接无隐含协议假设 | §6 C8 |
| 配置 | require 检查合法参数；功能开关保持约定接口 | §7 C9–C10 |

用原生 Reg、Mux 和适当辅助函数表达硬件；只有独立职责或技术需求才额外封装模块。
每次修改控制在用户任务所需范围内，不为风格改名造成公开接口变化。

## 审查硬件

沿接口和数据流检查上述关注点，对相关条款给出可定位证据。
输出发现使用：`位置 → 条款编号 → 功能/接口/风格类别 → 触发条件与影响 → 最小修正`。
教材对应条款引用 `4.x`，Chisel 补充引用 `C1–C11`；需要时附规范章节。
没有发现时说明已检查范围，不能据此声称所有配置或时序性质已验证。
仅请求审查时不直接修改代码；仅请求生成时不要附加无关全工程审计。

## 验证与交付

按规范 §8 C11，对实际改动选择必要的编译、elaboration 和行为测试。
重点覆盖相关边界，而不是为每条风格规则写测试。运行项目已有入口，
例如 `./scripts/sbt-local.sh 'testOnly <完整测试类名>'`；不要照抄占位命令直接执行。
需要 RTL 时检查实际生成结果的端口、位宽、状态和复位，测试包装层不进入生产接口。
只修改文档时不重新生成已有硬件。

交付说明改了什么、验证命令和结果，以及未验证事项。工具不可用时如实说明，
不以“应该通过”代替证据，不将仿真结果表述为综合质量或时序收敛保证。

并核对引用路径。不依赖原 PDF 存在才能执行已整理的规则。
